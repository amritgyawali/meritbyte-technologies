React Native is an open-source framework from Meta for building iOS and Android apps with React, written in JavaScript or TypeScript. The interface is built from real native components, so lists, text fields and navigation feel like the platform the user is on. The commercial argument is simple: if your website or web app is already built in React, the same people, patterns and much of the logic can build the mobile app too. Meritbyte Technologies is a Nepal-based development company that builds React Native apps for clients in Nepal and abroad.

## When is React Native the right choice?

React Native makes the most sense when:

- **You already have a React or Next.js web product.** Developers move between web and mobile, and validation rules, API clients and types are shared.
- **The app is mostly forms, lists, accounts and content,** which is most business apps: bookings, orders, portals, loyalty schemes.
- **You want to ship fixes fast.** With Expo's update service, JavaScript fixes can reach users without a full store release, within Apple's and Google's rules.
- **Hiring matters.** JavaScript and React developers are among the easiest to find, which keeps future maintenance affordable.

If you have no web team and want a highly custom, brand-heavy interface, [Flutter](/technologies/flutter) is often the better fit. If the app is built around heavy graphics or deep hardware access, fully native development may be. ## Expo and the modern React Native stack

React Native's own documentation recommends starting new projects with a framework, and Expo is the main one. Our default stack:

- **Expo** for project set-up, native modules and routing, with Expo Router for file-based navigation.
- **EAS Build and EAS Submit** for repeatable iOS and Android builds and store submissions from the pipeline.
- **EAS Update** for over-the-air JavaScript updates between store releases.
- **TypeScript** throughout, sharing types with the [React](/technologies/react) web app and the API.
- **The New Architecture,** now the default in React Native, for faster communication between JavaScript and native code.
- **Testing** with Jest and React Native Testing Library, plus end-to-end tests on real devices for the flows that make money. Our [QA and testing service](/services/qa-testing) covers device coverage.

## Sharing code between web and mobile

"Write once, run everywhere" oversells it. What we actually share between a React web app and a React Native app:

| Shared well | Usually separate |
| --- | --- |
| API clients and data types | Screen layouts and navigation |
| Validation rules and business logic | Platform-specific permissions |
| Design tokens: colours, spacing, type | Gestures and animations |
| Authentication and state management | Push notifications and deep links |

Done this way, a feature built for the web reaches mobile in a fraction of the time, without forcing a phone interface to look like a web page.

## Frequently asked questions

### What is React Native?

React Native is an open-source framework from Meta for building iOS and Android apps using React and JavaScript or TypeScript. It renders real native interface components rather than a web page, so apps feel native, while most of the code is shared between the two platforms.

### What is Expo, and do we need it?

Expo is a framework and set of services for React Native that handles project set-up, native modules, builds, store submission and over-the-air updates. React Native's documentation recommends starting new apps with a framework such as Expo. You can still add custom native code when a feature needs it.

### Can we update a React Native app without a store release?

Partly. Over-the-air services such as EAS Update can deliver JavaScript and asset changes, like bug fixes and copy changes, directly to installed apps, within Apple's and Google's rules. Changes to native code, permissions or the app's core purpose still need a normal store release and review.

### Should we choose React Native or Flutter?

Choose React Native if you already have React developers or a React web app, because people and logic can be shared. Choose Flutter if you are starting fresh and want a highly custom interface that looks identical on both platforms. Both produce real iOS and Android apps.
